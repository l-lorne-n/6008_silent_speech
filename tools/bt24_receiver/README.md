# BT24 电脑接收检查

这个工具用于确认 **电脑 → BLE 连接 → BT24 → 传感器数据接收** 是否正常。
它接收本仓库当前固件的六列 CSV：`raw0,raw1,filtered0,filtered1,envelope0,envelope1`。
它不会发送 AT 指令、修改模块参数，也不包含正式上位机的录制、波形和事件标记功能。

## 队友首次使用

1. 使用支持 BLE 的 Windows 10/11 电脑，打开电脑蓝牙。
2. 安装 [Python 3.12（Windows）](https://www.python.org/downloads/windows/)，安装时保留 Python Launcher 和 Tcl/Tk。已有 Python 3.12 可以跳过。
3. 下载或克隆整个仓库。如果下载 ZIP，**先完整解压**，然后进入 `tools/bt24_receiver/`。
4. 双击 `start.cmd`。首次启动会联网安装 BLE 依赖到本目录 `.deps/`；之后可以直接启动，不需要 Codex。

## 连接与接收

1. 关闭手机蓝牙，避免手机占用 BT24。
2. 给开发板和 BT24 上电，确认开发板已复位运行。STM32 PB14 → BT24 RXD，PB15 ← BT24 TXD；两端串口波特率均为 115200。
3. 在资源管理器中双击同目录的 `start.cmd`。
4. 点击“① 扫描 BT24”，等待约 8 秒；选中自己的 BT24 后点击“② 连接选中设备”。
5. 应看到累计字节、有效六列数据行数增加，下方持续出现数字。当前固件约输出 100 行/秒，不能将其当作完整的 1 kHz 或 2 kHz 采样数据。

**无需先在 Windows 设置中配对，不会产生 COM 口，也不需要在此工具中选择波特率。**
窗口显示的行率是短时间接收速率，BLE 的分批到达会使它波动；此工具不具备设备采样序号和 CRC，不能据此证明无丢样。

2026-10-28 已在开发电脑直接连接 BT24，短时接收到 23717 字节、799 行有效六列数据、0 行格式异常。
这证明当时的电脑 BLE 连接和文本接收通路可用，不代表正式完整采样的吞吐或无丢包验证。

## 如果无法接收

- 没有找到 BT24：确认模块供电、手机蓝牙已关闭，将 BT24 重新上电后扫描。扫描能找到其他 BLE 设备仅证明扫描工作，不证明目标模块连接正常。
- 连接失败：保持模块靠近电脑，确认手机没有重连；如反复失败，保留窗口完整报错。
- 已连接但 0 字节：确认开发板复位运行，PB14 → BT24 RXD，开发板和 BT24 的 UART 波特率一致。
- 有字节但没有有效行：查看实际内容；本工具仅解析当前六列文本固件，不解析正式二进制采集固件。

## 文件与依赖

`start.cmd` 优先寻找普通 Python 3.12（`py -3.12` 或 `python`），只在找不到时尝试本机 Codex 附带的 Python。
不绑定某个模块的地址，扫描列表中的 BT24 名称或 FFE0 服务作为候选，连接时请选择自己的设备。
BLE 库安装在此目录的 `.deps/`，不改动全局 Python 环境；依赖与缓存不上传 GitHub。
也可以使用支持 Tkinter 的 Python 3.12，在本目录手动执行：

```powershell
py -3.12 -m pip install --target .deps -r requirements.txt
py -3.12 receiver.py
```

仅扫描可双击启动脚本后按界面操作，或从终端运行 `start.cmd --scan`。

后续正式采集应为 v0.6.0 上位机增加 BLE 传输，再匹配正式采集固件的二进制协议，并实测持续传输、丢包及标记应答；本窗口只完成第一步链路检查。

参考：[BT24 厂家说明书](https://www.szdx-smart.com/static/upload/2025/10/23/202510234819.pdf)、[Bleak 文档](https://bleak.readthedocs.io/en/latest/)。
