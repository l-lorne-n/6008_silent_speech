开始使用
1. 双击 start_monitor.cmd；也可以运行 start.cmd，在主界面点击
   “信号采集 / 板端实时监测 · 选择模式与烧录”。
2. 保持“实时监测模式”、模型 mid64_temporal3，选择实际 CH340 串口，点“连接监测”。
3. 等待板端身份确认、1400 ms窗口预热，保持放松，让模型连续判断静息后解锁。
4. 点“开始十词提词测试”。默认每词1遍，可改次数；每轮十词随机。
   初始静息5秒，每词准备1.5秒、动作2秒、休息2秒。
   只在“现在动作”时自然做一次无声口型，不出声，之后放松。
5. 左侧为提示词，中间为当前100 ms滑窗的候选，右侧为板端连续确认后的命令。
   “候选”会随窗口改变；统计正确、错词、漏检使用的是确认命令。

词表固定为：open / close / next / music / louder / photo / previous /
quieter / start / stop / rest。rest 是静息类别，用于解锁，不作为要发音的指令。
提词标签只用于电脑评分，发送板端的仅是不含标签的时间标记编号。
没有让电脑先知道目标词再影响板端分类。

恢复信号采集
1. 结束提词，断开监测。
2. 选择“信号采集模式”，点“编译并烧录所选固件”。
   采集模式实际烧录已核验的 v0.6.0 2kHz HEX，无需重新编译。
3. 成功后点“返回信号采集界面”，选择完整采样二进制、230400、实际串口，按原流程录制。
4. 要回监测模式，再选监测模型并烧录，随后连接。
同一串口不能被主采集界面、监测界面或其他串口软件同时占用。
烧录时保留 CMSIS-DAP 调试器、板子供电及SWD连接，完成后不要按额外复位键才开始保存。

更换模型
下拉列表包含当前基模及这次结构对照的9个模型。
选择结果后，程序从对应冻结 INT8 ONNX 导出权重，生成独立工程，调用本机 Keil 编译，
备份板上第一Flash bank，按扇区烧录并逐字节校验，复位后板端回报模型名和SHA256前缀。
上位机核对所选模型与板上模型身份，不匹配时禁止开始提词测试。
mid64_temporal3 已完成实机数值、速度与GUI验证。
其他候选均已编译通过，但没有逐个烧录做同等数值和时延验证；换模型后看它自己的实时耗时。

计算位置与参数
板端：ADC每路2000Hz；因果20–500Hz带通、50Hz陷波；连续滤波状态；训练集归一化；
2800点双路滑窗，每200点运行一次；五层CNN；11类softmax；命令确认与静息解锁。
首次预测不补零，不读取未来样本，不按提示词边界重置。
冻结解码：阈值0.5，连续2窗确认，连续2窗静息，输出后至少500ms再允许静息解锁。
电脑：提词、接收板端结果、展示、保存、根据板端样本时刻评分。没有电脑端CNN后备推理。

运行时是本项目针对冻结QDQ图编写的C实现，不是已经做过ST Edge AI转换的模型。
Flash保留INT8权重，激活为INT8，累加为INT32；启动时将权重展开为INT16放在AXI SRAM，
使用Cortex-M7双乘加指令加速，权重数值不改变。少量缩放、滤波与softmax采用FP32。
已开启I/D Cache，DMA缓冲区位于MPU设为正常非缓存内存的D2 SRAM，避免缓存不一致。
原始采集工程不被覆盖，生成工程在 board/build/<模型名>/。

速度如何读
计时采用板端TIM2自由运行硬件定时器，分辨率1微秒，独立于调试器。
“纯推理”含网络与softmax；“每步流水线”再计入本步200点的滤波/归一化、窗口复制和解码。
中断保持开启，因此推理期间的采样中断开销也包含在实测时间中。
当前实测纯推理约68.1ms，流水线约68.3ms，低于200ms，也低于100ms步进。
这不是从开始发音到输出的延迟：1400ms历史窗口、等待下一个100ms步进、连续两窗确认
都会影响用户感到的响应速度；初始化至少等满1400ms。
测试报告中的 cue_to_correct_ms 是屏幕阶段标记应答到正确命令的近似间隔，
标记有10ms采样块粒度，没有测量屏幕实际发光时刻或真实肌肉动作起止。
实测并非所有硬件、温度、未来代码修改情况下的硬实时最坏时延证明。

已完成的验证
1. 原样备份、烧录及逐字节回读校验成功。
2. 18个归一化窗口：板端与ONNX Runtime的11个输出logit全部一致。
3. 五人共50个连续原始ADC窗口：最终类别50/50一致，最大logit误差约0.100863，
   即一个输出量化刻度；原因包括MCU FP32因果滤波与离线float64滤波的数值差异。
   这不是新的人体准确率测试，不能把50/50说成识别正确率100%。
4. 连续一分钟量级的实机监测：流水线最大约68.4ms，跳窗/板端丢包/CRC错误/设备故障均0。
5. 切回采集固件，实际收到24540对双路样本，无缺样/CRC错误/设备故障，标记ACK正常。
6. 监测GUI实际串口连接、模型身份核对、实时结果显示和提示标记ACK通过。
7. 协议、评分、2kHz采集与双通道相关自动检查通过；详见board/logs和交接记录。
