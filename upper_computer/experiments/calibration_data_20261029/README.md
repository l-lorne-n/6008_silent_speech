# 两种 LDA 校准方法的冻结实验包

使用当前 goodone_plus 五人、49 份录制、2496 个有效动作的 48 维特征。运行入口为上一级 `run_lda_calibration_comparison.py`；`--method fixed50_x40` 或 `--method pooled_k3_x10` 分别运行，默认两种都运行。`--reextract` 会从仓库中的原始录制重新提取特征，与冻结矩阵逐元素比较，然后训练。

| 方法 | 每人独立校准动作 | 校准复制次数 | 总测试数 | 总正确数 | 准确率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| fixed50_x40 | 50，每词5条 | 40 | 2246 | 915 | 40.74% |
| pooled_k3_x10 | 270或300，每份录制每词3条 | 10 | 1026 | 686 | 66.86% |

每折都加其他四人的全部有效动作，重新拟合全局 StandardScaler 和 LDA(lsqr, shrinkage=auto)，不使用额外的按人归一化。五个目标人各训练一个模型。两个方法有不同的校准预算和测试成员，不能把分数差值作为同条件的优劣比较。参考预测只用于训练完成后的验算，不进入拟合。

- `features.npy`：2496×48 矩阵，行号由 `trials.json` 固定。
- `trials.json`：相对录制路径、动作身份、指纹及事件时间。删除重复的特征数组，保留原始行序。
- `fixed50_splits.json`：原实验的 50 条校准和剩余测试索引，逐人复用。
- `pooled_k3_splits.json`：每份录制每词按 prepare 排序取最早3条有效动作的原始索引。
- `sources.json`：49份录制的196个核心源文件 SHA256；路径相对 upper_computer。
- `protocol.json`：配置、类别顺序、历史实验标识及时间检查。fixed50 保留原词表顺序，K=3 保留原实验的字母排序，避免改变数值处理顺序。
- `manifest.json`：冻结包各文件 SHA256 和预期总数。文档 README 不参与特征数据封存。
- `*_reference.json`：原实验的汇总及逐人统计。
- `*_predictions.csv`：原实验每个测试动作的预测，重跑要求逐条相同。

输出为新的 `upper_computer/models/lda_calibration_release_...`。每种方法含5个离线 JSON 模型、逐动作预测和 report.json；顶层 completed.json 记录数据校验、模型读回验证、加权标准化统计核对以及最终分数。这些模型不是 App 或 MCU 的现有 CNN 加载格式。

解释边界：固定50方案的校准录制与测试录制分离，但不代表独立佩戴，S012 含校准之前的测试录制；K=3方案共享录制并汇总后续校准，其中三份录制不是全校准先于全测试。重复次数是查看前序结果后探索的参数。所有分数为离线提示动作片段分类，不能当成零校准跨人泛化或在线控制成绩。完整流程和原实验路径见 [本轮交接](../../history/2026-10-29_LDA校准实验汇总与两方案报告交接.md)。
