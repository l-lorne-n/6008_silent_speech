### 2.2 采集与前处理

- 上位机/采集链路版本 v0.6.0，每通道 2000 Hz，UART 230400，板端发送原始 ADC。

- 训练侧拟合每通道标准化；补零应在标准化后进行。不能对测试集合整体重新拟合统计量。
- 历史上 S011/S012/S015 做过通道交换，之后按用户要求全部恢复。恢复采集顺序不等于已经证明电极的实际解剖位置。
- 不要同时递归读取原始 S015 和它的 `goodone` 副本，造成同一信号重复或跨集合泄漏。

### 2.3 “录制 2 秒”和模型窗口不是同一个概念

五人录制元数据通常为准备 1.5 s、动作 2 s、静息 2 s，基线 5/10 s。设备标记得到的动作区间中位数约 2.03 s，另有一条 S011 动作约 3 s。

- 2 s 是采集提示时间，不保证两秒一直有有效口型活动。
- 最初提示切段 CNN 去掉动作首尾各 150 ms，有效输入约 3380–5400 点，中位约 3460 点。
- 旧 CNN 与自动分段 SpeechNet 的输入容量都是 **6144 点＝3.072 s**，不足补零。它是容纳不同片段的上限，并不是每次真实说话都长 3.072 s，更不是 100 ms 步进的滑窗。
- 新滑窗 `window800/window1400` 分别指 800/1400 ms＝1600/2800 点；每 100 ms 更新一次。
- SpeechNet 的 `time_scaled` 指时间卷积核长度按 4 倍调整，不是把整段信号缩放时间，也不是选中了一个叫“57”的窗口。

上次讨论中，基于**仅训练侧、成功匹配的活动检测候选**得到以下时长估计：

| 人员 | 候选数 | 活动核心中位/P90（s） | 加前后各150 ms后的中位/P90（s） |
|---|---:|---:|---:|
| S011 | 257 | 0.62 / 1.06 | 0.92 / 1.36 |
| S012 | 242 | 0.90 / 1.596 | 1.20 / 1.896 |
| S013 | 296 | 1.41 / 1.84 | 1.71 / 2.14 |
| S014 | 279 | 1.06 / 1.648 | 1.36 / 1.948 |
| S015 | 272 | 1.17 / 2.018 | 1.47 / 2.318 |

这些是检测器估计，漏检没有进入统计，同一动作也可能有多个候选，不能当成人工真值或独立动作总数。用户提出“先确定五人真实时长再选窗口”是尚待继续处理的问题。800/1400 ms 是参考文献配置设立的首轮候选，尚不能认定最优；本次没有修改正在运行的候选表。

## 6. 方法二：活动检测器触发 CNN

入口：`experiments/replay_activity_cnn.py`；核心：`semg/activity_cnn.py`。
产物：`analysis/activity_cnn_replay_20261021`，包含49份连续滤波缓存、协议、选择记录、事件和逐试次报告。

流水线为：原始连续信号 → 因果滤波 → RMS活动检测 → 提取候选 → CNN十词分类。前级是基于阈值/状态机的活动检测器，不是另训练的词分类CNN；后级没有静息输出。

选中参数：

| 项目 | 设置 |
|---|---|
| 更新步长 / RMS包络窗 | 20 ms / 60 ms |
| 基线校准 | 开头5 s；跳过最初500 ms、削顶及其后200 ms；至少3 s干净基线 |
| 阈值 | 基线中位数/MAD及下限；启动倍率4，停止倍率2.2 |
| 双通道规则 | 任一路达到条件可启动；两路都回落才结束 |
| 启动确认 / 释放 / 重启等待 | 60 / 320 / 500 ms |
| 候选前后上下文 | 各150 ms |
| 活动核心时长 | 200–2700 ms；输入最大6144点 |
| 异常处理 | 过长拒绝；EOF不强制补一个输出 |
| 分类置信度阈值 | 验证选择0，即该版本不再按分类置信度拒识 |

比较9组检测配置×4个置信度（0/0.6/0.75/0.9），仅490条验证侧选择。检测器运行时不读提示标签；评分才事后匹配，至少100 ms重叠且覆盖候选活动的50%，要求唯一归属；跨划分候选拒绝。

检查发现：连续因果滤波后按已知提示切段，仍能重现约82.57%/79.16%；真正掉分主要出现在候选检测与分段输入变化后，不能简单归因于把离线滤波换成因果滤波。原模型连续成绩见第3节。

## 8. SpeechNet 双通道适配实验（已完成）

入口：`experiments/run_speechnet_comparison.py`；结构：`experiments/speechnet_two_channel.py`；PowerShell封装：`run_speechnet_comparison.ps1`。
结果：**`models/speechnet2_20261021_171418`**。

### 8.1 与旧 CNN 的结构区别

```text
输入：双电极 × 6144点，自动片段不足补零
三层时间卷积：各电极分别提取，电极间共享权重
第四层 2×1 空间卷积：融合两个电极
第五层 1×1 卷积：融合特征
全局平均池化 → Dropout0.5 → Linear(10)
```

五层输出宽度8/16/16/32/32，每层BN、ReLU；时间池化8/4/4，后两层池化1。它是五层卷积，其中前三层做时间特征提取，不是沿用原32/64/128再简单加两层。

| 候选 | 前三层时间核 | 参数量 |
|---|---|---:|
| `paper_kernels` | 4 / 16 / 8 | 6818 |
| `time_scaled` | 16 / 64 / 32 | 19202 |

核长度乘4是考虑论文500 Hz、本项目2000 Hz的采样率差异；池化等未完整等效变换，因此不能说是严格复现同一物理感受野。

训练：2候选×3种子20261010/11/12；Adam（区别于旧AdamW），lr0.001、weight decay0.0001、batch32，最多100轮，早停10；ReduceLROnPlateau factor0.1、patience2；保留自动片段的边界、时间平移和增益增强。数据仍1340/440，最终1780；按验证CE选结构、种子和轮数。

### 8.2 第57轮到底表示什么

选中 `time_scaled / seed20261012 / epoch57`，验证75.6818%、CE0.817157。该候选实际上训练到67轮，因为最佳57轮后连续10轮未改善而停止；最后用1780条从头重训57轮。

重训复用选中轨迹：1–35轮lr0.001，36–50轮0.0001，51–57轮0.00001。不是训练到第57轮就碰巧停止，也不是第57轮测试成绩最好。

三个种子在各自验证CE最佳点的准确率：原核61.14/49.09/64.09%；长核74.77/71.14/75.68%。整个开发训练及最终重训约1620.5秒。

INT8 PTQ由开发验证CE选99.9：验证75.00%、CE0.82019；99.99虽然验证准确率76.136%，但损失更高，所以未选。最终INT8较FP32多6条正确，是本次观察，不代表量化必然提高准确率。

### 8.4 论文与当前实现的边界

参考：[SilentWear论文](https://arxiv.org/html/2603.02847v2)、[作者仓库](https://github.com/pulp-bio/SilentWear)；本地 `L:\ntu_class\6008\silent_wear\SilentWear`。许可证/来源说明保留在 `experiments/third_party`。

| 项目 | 论文 | 本项目已完成SpeechNet |
|---|---|---|
| 输入 | 14通道，500 Hz | 2通道，2000 Hz |
| 类别 | 8词＋静息 | 10词，没有静息类 |
| 模型组织 | 按人/条件训练及同人跨session适配 | 五人混合一个模型 |
| 空间核 | 两个7×1 | 2×1和1×1 |

## 9. 新方案：滑动窗口＋静息类（已完成首轮）

入口：`experiments/run_sliding_rest.py`；核心：`experiments/sliding_speech.py`；用户说明：`滑动窗口静息类运行说明.txt`。

### 9.1 网络、训练和防静息偏置

最近800/1400 ms双通道连续波形 → 每100 ms送CNN → 十词＋rest概率 → 因果确认/锁定状态机 → 命令。**不使用前面的RMS活动检测器触发推理**，但仍有把逐窗概率变为单次命令的解码逻辑。

- 结构采用SpeechNet长核16/64/32、空间2×1/1×1、宽度8/16/16/32/32、Dropout0.5，全局池化随窗口长度适配，最后11输出。
- 两种窗口×三个种子，最多100轮，早停10；Adam lr0.001、wd0.0001，ReduceLROnPlateau factor0.1/patience2，batch44。
- **每轮每类400窗口，共4400；静息只占1/11＝9.09%**。类内先均衡人员，再抽试次、窗口；训练可有放回，每轮换随机采样。不再叠加静息大权重。
- 固定不重复验证子集，每类最多200个窗口；11类宏平均CE选择窗口/种子/轮数。不能按包含大量静息的总体窗口准确率选赢家。
- 数据增强仅每通道增益0.9–1.1，自然滑窗提供时间对齐变化；不做补零平移或整波形时间缩放。
- 先固定原整轮划分，再生成窗口；训练侧唯一连续采样点拟合标准化，不能把重叠点重复计权，更不能把相邻重叠窗口随机拆到不同集合。
- 最终训练合并原训练＋验证上下文，复用选中的轮数及学习率轨迹。

原始候选窗口：800 ms共66024，1400 ms共31309；800 ms训练rest18053、每词约2158–2189；1400 ms训练rest3893、每词约1473–1511。它们是重叠窗口数，不是新增独立动作数。均衡采样降低静息数量占优风险，但不保证完全没有静息偏置或过拟合。

### 9.2 标签规则

窗口必须完整位于同一原试次上下文，不跨训练/验证/测试边界。

- 词窗口：至少75%的窗口与提示动作区间重叠，窗口结束在动作开始150 ms之后且不晚于动作结束。
- 静息窗口：完整位于受保护准备区（prepare后200 ms到action前200 ms）或静息区（rest后300 ms到上下文结束前100 ms）。
- 过渡/含糊窗口不强行贴rest；不参与监督损失，但连续回放仍然逐窗推理它们。
- 削顶窗口不作为正常训练标签。

这些仍是提示代理标签，不是人工标注的真实肌肉起止；没有使用旧检测器把所有窗口先分成词/静息。长窗口约2 s的进一步实验尚未实现，因为当前静息区2 s减去保护边界后不足容纳纯静息长窗口，不能只改一个长度常数。

### 9.3 PTQ与命令解码

训练侧按类及人员/试次均衡校准，最多50个独有窗口/类（550总上限）；验证宏CE选择MinMax/99.99/99.9/99.5。最终训练侧按冻结设置重新校准。

用**开发训练模型的INT8版本**在连续验证区间挑解码参数；不能用已经见过验证数据的最终重训模型调验证阈值。24组组合：词概率0.5/0.65/0.8，类别分差0/0.15，同词连续2/3帧，静息连续2/3帧。

解码器初始未启用，先要求rest为最大概率且至少0.5、连续满足指定帧数；然后连续同词满足阈值才输出。输出后锁定，至少500 ms且再次连续识别到rest后才能重新启用。全程不读取提示/真值，不在每条命令开头强制复位。验证选择顺序：严格成功率、事件F1、较少静息输出。FP32/INT8最终测试共享冻结规则。

### 9.4 评估脚本已适配，不照搬旧68.14%

新方案按原划分的最大连续区间滑动推理，窗口/解码历史不跨入其他集合；只在划分区间边界重置，不按每个词重置。开头积累窗口和确认静息造成的漏命令仍计入499。因果滤波保留既有完整录制缓存的滤波器历史。

新评分统一以**输出时刻**归属：响应区间 `[cue_action, cue_rest+300ms)`，受试次上下文右边界限制；每条命令最多一次成功。严格成功要求整个prepare到下一prepare上下文只有一个输出，并且该输出在响应区间内且类别正确。

报告保留全部499条命令，另报无响应、错误词、重复、响应区间外输出、提示静息每分钟输出、精确率、事件F1及逐人明细。全预测rest模型的命令识别率是0%，不会借静息多数取得虚高主成绩。

旧提示CNN、自动32、gated SpeechNet的INT8输出事件会按新规则重算。因此新报告中的旧基线数字可能不同于68.14%，应看同一份 `comparison`。旧检测器全录制状态与新方案按划分边界重置仍有运行边界差异，不应称严格单因素实验；也不能把整份录制约239分钟都称独立测试。

权重默认考虑放Flash；上述RAM预算是保守张量清单加预留，既不是ST实际arena，也不是实测占用。用户询问的“473减256是否实际217”应答：约217是张量估算部分，不等于实际总RAM只有217 KiB。算子融合/复用会降低某些占用，scratch和接口转换又可能增加占用，必须经ST工具链和板上验证。
