# sEMG 提词采集上位机核查与实施方案

核查日期：2026-09-23。本文件保留开发前的核查和设计建议。后续首版程序及固件副本已实现，使用方法、实际实现范围和验证状态见同目录 README.md；板上固件尚未替换。最终首批词表为 open、close、next、music。

建议做一个 Windows 桌面采集程序，把串口接收、提词、事件标记、连续数据保存和简单波形监控放在一起。SerialPlot 可以继续用于单独调试，正式采集由上位机接管串口。先解决完整采样和时间对齐，再开始批量采集用于 LDA 的数据。

## 2. 当前工程实际在做什么

| 项目 | 核查结果 | 代码依据 |
|---|---|---|
| MCU | STM32H743VGTx | uvprojx 的 Device 字段 |
| 物理采集通道 | 1 路，ADC1_INP7，PA7 | main.c:300；MSP 的 ADC GPIO 配置 |
| ADC | 16 位，硬件 16 倍过采样、右移 4 位 | main.c:268 起 |
| 触发 | TIM3 TRGO，DMA 循环采集 | main.c:274 起 |

| 数字滤波 | VERIFY_MODE=2；四个二阶节，代码标注 20–400 Hz 带通 | main.c:54、498 起 |
| 包络 | 带通信号取绝对值，再做 200 点滑动平均，约 200 ms | main.c:57、165、473 起 |
| 串口 | USART1，115200，8N1，无硬件流控；PB14 TX / PB15 RX | main.c:378 起；MSP UART 配置 |

| 样本时间信息 | 没有采样序号、设备时间、帧号或校验 | 当前 printf 格式 |

SerialPlot 的三条曲线是同一物理通道的三种表示，不是三路独立 sEMG。第一条为 ADC 码值，不能未经增益、参考电压校准就标为肌肉电压 µV。源代码采用 32768 作数字中心；截图约 33800 的静态基线不单独证明故障，仍应检查实际直流偏置、动态范围和动作响应。

## 3. 正式采集前需要处理的问题

### 3.1 当前电脑收到的不是完整 1 kHz 波形

程序先在 1 kHz 下滤波，再每 10 点只保留一个输出。原始 ADC 和带通列丢掉了其余 90% 的点，且没有适配 100 Hz 输出的抗混叠低通。100 Hz 输出的 Nyquist 频率只有 50 Hz，无法保留原本 20–400 Hz 带内信息。

因此这些串口列可用于联调，但不应按完整 1 kHz sEMG 计算 RMS、ZCR、波形长度和频谱特征。包络仍可用于粗略观察活动，但不能替代原始波形。降采样前需抗混叠滤波，这是 [SciPy decimate 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.decimate.html) 明确采用的流程。

正式采集建议发送完整原始 ADC 数据；主机显示可以稀疏刷新，磁盘保存不能跟着丢点。

### 3.2 串口接收时刻不能当成采样时刻

当前等半块 500 点完成后，主循环才开始处理、逐字符 printf 发送。在标称 1 kHz 下，块内较早样本等待接近 0.5 秒，较晚样本等待较短；另外还有 UART、USB 和操作系统缓冲延迟。这不是所有样本都能减去一个固定 500 ms 来修正的问题。

如果在屏幕切换词语时，直接给“此刻收到的行”打标签，收到的可能是之前休息阶段的数据。现有格式缺少设备序号，事后也无法可靠查清中间漏了多少点。

### 3.3 不能只把 PRINT_EVERY 从 10 改成 1

115200、8N1 的理论有效字节容量约 11520 bytes/s。当前三列文本每行长度可变，1 kHz 连续发送可能超过容量；逐字符阻塞发送还会占用处理时间。当前半块/满块标志都是布尔值，若处理赶不上，存在缓冲区覆盖和未计数丢块风险；这属于风险分析，尚未实测发生。

首版可保持 115200，用小块二进制发送原始 uint16 数据：1 通道 × 1000 × 2 = 2000 bytes/s，加包头和校验仍有余量。如果保留三列全速文本，则需重新计算最坏字节率、提高波特率并验证链路，不能假设修改一项参数即可。

### 3.4 文档参数应以实际硬件为准

计划中写过 20–500 Hz；在 1 kHz 采样下，500 Hz 位于 Nyquist 边界，不应直接作为常规数字带通上截止。当前 20–400 Hz 可作为首版处理设定，后续结合前端带宽、频谱和工频干扰决定是否需要 50 Hz 陷波。

现有 schema 中的 6 通道、12 位、增益 1000、单位 µV 是示例，不应照抄到本次数据。当前已知的是 1 通道、16 位、单位 ADC counts；模拟增益等未知项应标为未确认。

## 4. 建议的首版程序

采用 Python + PySide6 桌面程序，QSerialPort 管串口，PyQtGraph 显示波形。理由是与后续 Python 特征提取和 LDA 共用数据结构，便于在本机运行；不是要求改用新的云服务。

[Qt 官方文档](https://doc.qt.io/qtforpython-6/PySide6/QtSerialPort/QSerialPort.html) 提供串口枚举和异步读取能力，并说明串口独占访问及 GUI 线程内阻塞读取的问题。[PyQtGraph 官方文档](https://pyqtgraph.readthedocs.io/en/latest/) 描述了其 Qt 科学绘图能力。

程序包括：

1. **连接与检查**：选择 COM 口、显示固件/协议版本、标称及接收采样率、丢包数、数据保存路径。端口被占用时明确提示关闭 SerialPlot 的连接。
2. **采集配置**：受试者 S01、session、batch、贴片位置、动作条件、词表、每词次数、阶段时长、随机种子。
3. **参与者提词窗**：大字显示词语、准备/开始/休息状态、倒计时；可以全屏。统一指令为“保持闭唇，内部尝试发音一次，不出声”，避免混入自然张嘴做口型或仅在脑中默念的试次。
4. **操作员监控**：实时波形、包络和质量提示；显示刷新可为 20–30 次/秒，接收与保存仍按全部样本进行。
5. **采集控制**：开始、暂停、终止、当前试次作废、补录。受试者在动作期间无需按键。
6. **数据保存**：连续样本与事件分开写入；断线、磁盘错误、接收溢出必须显式报错，不能仍显示正常录制。

串口接收/解码、文件写入、GUI 刷新相互解耦；有界队列满了须产生错误和质量标记，不能静默删除旧样本。持续接收过程中不为画图或换词清空串口缓冲。

## 5. 提词流程草案

以下时长是待试采调整的初始值，不是已验证实验参数。

```text
连接检查 → 10 s 静息记录 → 多个随机化小组

每次试次：
准备/看词 1.5 s → 保持闭唇，内部发音一次 2.0 s → 放松休息 2.0 s
```

动作区间先规定每次只完成一次词语，完成后放松，不在 2 秒内不停重复。嘴唇自然闭合，避免额外刻意咬紧牙齿来制造更大的信号；若有咬牙等操作，单独标注。闭唇条件下先通过少量试采验证信号可重复性和词间差异，不能用咬牙时可见波形来证明词语可以区分。若要采重复动作或自然无声口型，应另设协议版本/动作条件，不能混用。准备阶段可能有提前动作，因此应单独保存 prepare 状态，不能直接当纯静息训练数据。

每个小组让全部词各出现一次，组内随机排序，保存随机种子和实际顺序。先做少量练习，再试采 3–5 个差异较大的词，每词 5–10 次，验证信号和标签后扩展到文档中的 10 词 × 20 次。每完成约 20–30 个试次安排休息，具体间隔可配置。

暂停或断线若发生在动作期间，该试次标记 interrupted，不把前后两段拼成一次完整试次。补录分配新的 trial_id，并引用原试次，保留原数据和作废原因。

按每试次 5.5 秒计算，10 词 × 20 次约 18.3 分钟/人，5 人约 91.7 分钟纯试次时间，尚未包含贴片、检查、练习、休息和重录。

## 6. 时间对齐设计

目标是知道每段提示与设备采样轴的关系，并保存误差线索；不能把提示开始等同于真实肌肉动作开始。

### 必须保存的三类时间

- **设备采样轴**：设备端 sample_idx，按 ADC 采样进度增长，即使发送失败也不能重新连续编号掩盖丢点；记录 nominal_fs 和设备重启边界。
- **电脑事件轴**：同一单调时钟下记录准备、开始、结束、暂停、重录，以及串口接收批次时刻。可用 [Python perf_counter_ns](https://docs.python.org/3/library/time.html#time.perf_counter_ns)；纳秒单位不代表实际同步精度达到纳秒。
- **会话日期**：另存 UTC 开始时间与本地时区，便于文件追溯，不用墙钟跳变驱动阶段计时。

### 推荐的同步方法

固件支持 `SYNC` 和带唯一 event_id 的 `MARK` 控制消息。主机保存发送与应答接收时刻，板子应答设备计时和当时的采样位置；同步应多次执行并定期更新，用往返时延识别异常和估计时钟映射/漂移。

事件标记中的采样位置必须来自实际采集进度，例如 DMA 进度结合完成块计数的一致快照，不能使用主循环“已经处理/已经发出多少点”的计数代替。需要明确 sample_idx 表示最近完成还是下一次待采样，并处理块边界竞态、计数回绕和重启。

发送 MARK 的软件时刻、板子收到 MARK 的时刻、显示更新提交时刻分别保存。板子 ACK 只能说明板子收到标记，不能证明屏幕在同一时刻亮出提示。首版可以采用软件同步近似，同时记录 RTT、映射残差和异常；未经测量不能承诺毫秒级光学呈现精度。若以后确需精确刺激时刻，可用屏幕光电检测/硬件触发共同采样来验证。

真实动作起止之后可结合包络及人工复核标注，分别保留 cue_onset/cue_offset 与 activity_onset/activity_offset，不覆盖原始事件。

## 7. 固件调整范围建议

建议在新的固件副本中实施并保留现有可用工程。修改副本、补丁和构建说明也放在 upper_computer 下，是否烧录由后续实施范围决定。

- 保留现有 ADC/TIM3 基本采样设置，正式输出完整原始 ADC。
- 将 DMA 处理块缩小到约 10–20 ms，例如总缓冲 40 点、每半块 20 点，实测确认中断与处理余量。
- 用帧头、版本、消息类型、长度、帧号、首样本序号、样本数、通道数、原始 uint16 负载和 CRC 的二进制帧；具体字节序、字段宽度、CRC 参数在实施时形成单一协议定义。
- 用 UART DMA 和有界发送队列；发送尚未结束的缓冲不能被复用。增加溢出/丢块计数。
- 增加 HELLO/INFO、SYNC、MARK/ACK 控制消息。UART 配置成 TX_RX 并不意味着当前程序已经实现接收命令。
- 主机接收完整原始数据后计算滤波与包络供显示；如果继续发送板上滤波结果，要同时保留原始列和滤波版本。

无需先做这些修改也能开发一个兼容 `raw,filtered,envelope` 的旧格式联调模式，但该模式必须写明 100 Hz 输出、无设备序号、时间对齐未验证。不能把主机自动编号冒充设备采样序号，不能静默升级成正式数据。

## 8. 保存结构与 LDA 接口

建议首版持续写入可检查的样本文件、事件文件和元数据，结束后再生成训练使用的 HDF5。以下是拟定文件结构，尚未生成数据：

```text
upper_computer/
  recordings/S01/session_001/batch_001/
    samples.csv
    events.csv
    trials.csv
    metadata.json
    transport.bin
    recording.log
```

- `samples.csv`：设备启动段 ID、sample_idx、原始 ADC 列 raw_ch0、接收批次 ID。若保留板上滤波列，用明确的 derived 名称。设备采样时间由采样轴推导；主机接收批次时间另外保存。
- `events.csv`：event_id、trial_id、事件类型、计划事件时刻、实际软件事件时刻、标记发送/应答时刻、设备确认 sample_idx、同步状态。丢失 ACK 的事件标为未确认。
- `trials.csv`：trial_id、label_id、词语、组号、各阶段事件引用、valid/rejected/interrupted、补录关联和原因。
- `metadata.json`：匿名受试者、session/batch、动作定义、词表映射、随机种子、实际顺序、采样率、通道、单位、贴片/参考电极位置、固件和主机版本、滤波设置、协议版本、同步统计、丢包/重启统计。
- `transport.bin`：原始接收字节，供重放、重新解码和定位问题。实际试采与模拟测试必须分目录和标识。

持续保存静息和准备区间，不只截取动作区间。保留不可修改的原始事件，再派生训练标签；缺失样本显式保留缺口，不能压缩时间轴伪装成连续采样。

后续可导出项目现有 schema 的 `/emg` HDF5，当前仅使用 `Ch_0`，单位注明 ADC counts；派生 `Ch_0_filt`，增加 Label_int/Label_str、subject_id、session_id、batch_id、trial_id、sample_idx、quality_flag。标签映射区分 rest、prepare、action 和无效区间。

LDA 阶段从有效试次提取 RMS、MAV、波形长度、带阈值的 ZCR 等特征。训练/测试按完整试次或 session 分组，跨人实验按人留出；同一次动作切出的重叠窗口不能随机散入训练和测试。标准化等拟合步骤只使用训练集。当前单通道可以验证端到端流程，但不能据此预先保证 10 词或跨人识别效果。

## 9. 推荐实施顺序与验收

1. 动作定义已确定为闭唇内部发音，首批词表仍待确定；先实现提词状态机、模拟数据和文件写入，验证暂停/补录逻辑。
2. 做旧格式联调适配，检查真实串口内容、行率和突发发送行为；这一步的数据单独标记为联调数据。
3. 修改固件副本，完成全速原始数据、序号、小块传输及同步标记，再用真实设备联调。
4. 连续录制至少数分钟，检查采样计数与时长一致性、序号缺口、CRC、重启检测和写盘失败行为；所有丢失均可追踪。
5. 进行少量试采，回放波形和提示事件，检查动作是否落在预期区间；必要时扩大前后余量，不能靠主观假设宣布同步通过。
6. 人工复核后再批量采集，最后接特征提取和 LDA。

本次结论：可以去掉对 SerialPlot 的运行依赖，但应保留上位机内的简单质量监控。最先需要解决的是完整数据与可靠标签，然后才是界面细化和分类器。
